# Payments Plugin development

This repository is one Cargo crate and one production plugin process, `tempo`. Engine, wallet, protocol types, and native Tempo operations are internal modules. Keep Mesh core currency agnostic. The running plugin always provides payments and refundable identity bonds through one wallet and journal. Prices, bond publication and provider bond requirements are independently optional. Lightning lives in the independent LN Payments Plugin repository.

Tempo uses one long-lived MPP payment channel per buyer and seller, with OUSD for payment and gas. Buyer configuration and the `control` commands mirror the LN Payments Plugin where they apply. Select `wallet.network` explicitly for mainnet (chain 4217); the default is Moderato testnet (chain 42431). Keep the wallet profile and state database bound to their network, and use a separate `data_dir` when switching. Do not change the asset, network, funding, or refund guarantees implicitly. Network wallet creation, faucet funding, and blockchain transactions require explicit user authorization. Never send mainnet transactions while developing. Routine tests remain deterministic and offline. Never log keys, passwords, invitations, or raw signed transactions.

Run Cargo commands serially. Use `just check`, `just test`, `just doc`, and `just package`; preserve the lockfile and immutable Mesh dependency pin. Public API and documentation changes require `cargo doc`. Tests use deterministic temporary wallets and loopback fixtures. `offline-fixture` enables separate test executables; normal startup must never select a fabricated backend from configuration or environment. Production packaging builds only the normal binary without fixture features.

Preserve unresolved obligations, immutable agreements, original signed bytes, and unknown usage across restarts of this version. Do not invent zero usage or replay dispatched inference. This is new code without prototype migration requirements. Keep journal and ledger ownership locks, wallet/node pins, and transaction idempotency intact.

Keep changes focused and comments accurate. Avoid large comment blocks at function starts. Do not push to a remote or bypass commit hooks. Commit bodies are required, wrap at 72 columns, and must be reviewed when amending. Do not add co-author trailers. Avoid em dashes in prose and hard wrapping Markdown paragraphs.
